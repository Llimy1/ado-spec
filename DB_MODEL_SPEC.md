# ADO Database Model Specification

This document is the canonical relational data contract for ADO v1.

It turns the master specification into TypeORM/PostgreSQL entities and tables. It is not a
database migration and it does not authorize a model to bypass policy or the
State Machine.

Related documents:

- `DATABASE_CONSTRAINTS.md`: PostgreSQL, locking, indexes, and migration rules.
- `DATA_LIFECYCLE.md`: creation, supersession, retention, recovery, and deletion.
- `DATABASE_ERD.md`: relationship map.
- `POLICY_STATE_CONSTRAINTS.md`: authority over state changes.

## 1. Scope And Invariants

The database records facts, claims, decisions, and evidence. It is the single
source of truth for orchestration state. Files in artifact storage and ADO
worktrees are addressed by database records; they are not authoritative on
their own.

The following invariants are mandatory:

1. Every durable record has a UUID primary key and UTC `created_at` timestamp.
2. Human-readable keys are separate from primary keys and are never inferred
   from mutable names.
3. Every project-scoped record has a non-null `project_id`, directly or through
   an immutable parent relationship. Cross-project references are forbidden.
4. Business state is owned by `state.StateSubject.current_status`; an agent,
   runner, view, or integration cannot set it directly.
5. Artifacts, decisions, transition requests, state transitions, and audit
   events are append-only facts. Correction creates a successor, revocation,
   or explicit terminal status instead of overwriting history.
6. Raw secrets, raw PII, raw production data, and raw credential values are
   never persisted. Only approved references, classifications, and redacted
   representations may be stored.
7. A retry creates a new `JobAttempt`. It never rewrites a completed attempt.
8. A failed relational constraint is a domain failure, not an exception to be
   silently repaired by a worker.

## 2. Shared Modeling Conventions

### 2.1 Base Fields

All durable models inherit the following logical fields:

| Field | Type | Rule |
|---|---|---|
| `id` | UUID | Primary key, generated by the application or PostgreSQL. |
| `created_at` | timestamptz | Immutable UTC creation timestamp. |
| `created_by_actor_id` | FK Actor, nullable | Required when an actor is known. |
| `updated_at` | timestamptz | Allowed only on explicitly mutable operational rows. |
| `version` | positive integer | Starts at 1; incremented only for mutable configuration records. |

Append-only tables omit `updated_at` and `version` unless a redaction or
retention pointer needs to be recorded. All timestamps use `timestamptz`.

### 2.2 `core.SpecLibraryRevision`

`SpecLibraryRevision` records the approved immutable ADO Spec Library manifest
that governed a Project and its execution packets. It is append-only except for
its terminal availability classification.

| Field | Type | Rule |
|---|---|---|
| `revision_key` | varchar | Unique stable human key. |
| `repository_identity` | varchar | Canonical remote identity, never a local path. |
| `commit_sha` | char(40) | Full immutable Git commit SHA. |
| `approved_ref` | varchar | Protected branch or signed tag used for approval. |
| `manifest_sha256` | char(64) | Imported manifest integrity hash. |
| `manifest_artifact_id` | FK Artifact | Required immutable manifest Artifact. |
| `status` | enum | `approved`, `deprecated`, or `revoked`. |
| `approved_by_actor_id` | FK Actor | Required Human Owner actor. |
| `approved_at` | timestamptz | Immutable approval time. |

Unique constraints: `(repository_identity, commit_sha)` and
`manifest_sha256`. A revoked revision cannot be selected for a new packet or
run. Historical records retain their foreign key to it.

### 2.3 Keys, Enums, And JSON

- TypeScript string-union or `as const` enum values are lowercase ASCII stable
  machine values; database columns store those values explicitly.
- User-facing labels are stored separately or derived in the UI; labels are not
  enum values.
- JSONB is limited to schema-versioned runner payloads, policy details,
  display metadata, and provider-specific data that has no stable relational
  query need. Required query fields must be columns.
- `human_key` is immutable after approval. A display name may change.
- SHA-256 digests are lowercase 64-character hexadecimal strings.
- URLs, command arguments, file paths, and external IDs are treated as
  untrusted input and validated before use.

### 2.4 Actor And Scope References

`core.Actor` is the durable identity used by audit records. It has:

| Field | Type | Notes |
|---|---|---|
| `actor_type` | enum | `human`, `system`, `worker`, `codex`, `local_model`, `claude_import`, `github`, `unknown`. |
| `actor_key` | varchar | Stable non-secret key, unique with `actor_type`. |
| `user_account_id` | FK `auth.UserAccount`, nullable | Required for `human`; null for non-human actors. |
| `display_name` | varchar | Presentation only. |
| `is_active` | boolean | Inactive actors cannot initiate new work. |

Unique constraint: `(actor_type, actor_key)`. A `human` actor must have a
`user_account_id`; a non-human actor must not. Enforce this with a check
constraint.

Every table below records scope using real foreign keys whenever the target is
known. ADO deliberately does not use polymorphic ORM relations for critical
state or evidence references because it cannot provide database-level
referential integrity.

## 3. Canonical Status Ownership

`state.StateSubject` is the state ledger for every stateful entity. A stateful
domain record holds a one-to-one `state_subject_id`; `StateSubject` holds the
authoritative `current_status` and `previous_status`.

| Field | Type | Rule |
|---|---|---|
| `subject_type` | enum | Exact v1 target type from `transition_request.schema.json`. |
| `subject_key` | varchar | Immutable human key or UUID string used in packets. |
| `project_id` | FK Project | Non-null, scope anchor. |
| `current_status` | varchar | Only StateMachine transaction updates it. |
| `previous_status` | varchar, nullable | Previous value for incident recovery. |
| `is_terminal` | boolean | Derived/set in the same StateMachine transaction. |
| `status_updated_at` | timestamptz | Updated with `current_status`. |

Unique constraints: `(project_id, subject_type, subject_key)` and the reverse
one-to-one relation from each stateful owner. The service creating a stateful
owner creates its `StateSubject` in the same transaction and validates that
the subject type matches the owner. This keeps transitions relationally
addressable without a polymorphic foreign key.

`StateSubject` is not a shortcut for direct status writes. The only permitted
write service is `state.apply_transition`.

## 4. Project And Configuration Tables

### 4.1 `projects.Project`

| Field | Type | Notes |
|---|---|---|
| `project_key` | varchar | Globally unique, immutable after activation. |
| `name` | varchar | Product/service name. |
| `description` | text | Sanitized project summary. |
| `active_spec_library_revision_id` | FK SpecLibraryRevision | Required after Project activation; governs new packets by default. |
| `active_constraint_profile_id` | FK ProjectConstraintProfile, nullable | Set only after human approval. |
| `timezone` | varchar | IANA timezone for display/scheduling. |
| `is_archived` | boolean | Project configuration lifecycle, false by default. |

### 4.2 `projects.Repository`

| Field | Type | Notes |
|---|---|---|
| `project_id` | FK Project | Required. |
| `repository_key` | varchar | Unique within Project. |
| `remote_url_redacted` | varchar | Public non-credential-bearing URL. |
| `visibility` | enum | `public` only for managed Project v1. |
| `default_branch` | varchar | Informational only. |
| `integration_branch` | varchar | Required, normally `integrate`. |
| `protected_branches` | JSONB | Approved branch names, never authorization source by itself. |
| `is_active` | boolean | Prevents new work when false. |

Unique constraint: `(project_id, repository_key)` plus a partial unique index
for one active Repository per Project. Check that `visibility='public'`,
`integration_branch` is non-empty, and it is not a protected `main` target.

### 4.3 `projects.Component` And `ComponentRepository`

`Component` represents a product surface such as `server`, `web`, `ios`, or
`design`. It has `(project_id, component_key)` unique, `component_type`,
`display_name`, `is_active`, and `is_required_for_feature_default`.

`ComponentRepository` is an explicit mapping from component to repository:

| Field | Type | Notes |
|---|---|---|
| `component_id` | FK Component | Required. |
| `repository_id` | FK Repository | Required, same Project. |
| `relative_root` | varchar | POSIX relative path, normalized. |
| `is_primary` | boolean | Exactly one primary mapping per Component. |

Unique constraints: `(component_id, repository_id, relative_root)` and a
partial unique constraint on `component_id WHERE is_primary`.

### 4.4 `projects.EnvironmentProfile`

Environment profiles describe safe execution environments, not secrets.
Fields: `project_id`, `environment_key`, `purpose`, `allowed_network`,
`allowed_env_names`, `secret_reference_names`, `is_production`, `is_active`,
and `configuration_json`. Unique `(project_id, environment_key)`. A profile
with `is_production=true` cannot be selected by an automatable v1 Job.

### 4.5 `projects.ProjectConstraintProfile`

This is the DB representation of
`schemas/project_constraint_profile.schema.json`.

Fields: `project_id`, `profile_version`, `status`, `source_artifact_id`,
`content_sha256`, `identity_json`, `components_json`, `design_json`,
`architecture_json`, `verification_json`, `forbidden_behavior_json`,
`open_questions_json`, `approved_by_decision_id`, `activated_at`, and
`supersedes_id`.

Unique constraints: `(project_id, profile_version)`, one partial unique active
profile per project, and one-to-one `source_artifact_id`. A profile can become
`active` only through a HumanDecision-backed configuration service that writes
an ApprovalEvent and AuditEvent in one transaction.

## 5. Planning Tables

### 5.1 `planning.Roadmap` And `RoadmapSource`

`Roadmap` holds `project_id`, `roadmap_key`, `title`, `summary`,
`status_subject_id`, `source_version`, and `approved_at`. Unique
`(project_id, roadmap_key)`.

`RoadmapSource` is an append-only source binding: `roadmap_id`, `artifact_id`,
`source_kind`, `source_version`, `imported_by_actor_id`, `is_current`, and
`content_sha256`. Only one current source exists per roadmap through a partial
unique constraint. Supersession creates a new source record.

### 5.2 `planning.FeatureUnit`

| Field | Type | Notes |
|---|---|---|
| `roadmap_id` | FK Roadmap | Required. |
| `feature_unit_key` | varchar | Unique within Roadmap. |
| `title` | varchar | Human-verifiable outcome. |
| `intent` | text | Why this unit exists. |
| `risk_level` | enum | v1 risk taxonomy. |
| `status_subject_id` | one-to-one StateSubject | Feature lifecycle. |
| `constraint_profile_id` | FK ProjectConstraintProfile | Immutable binding once approved. |
| `sequence_number` | positive integer | Display/order only. |

Unique constraints: `(roadmap_id, feature_unit_key)` and
`(roadmap_id, sequence_number)`. A Feature Unit must not be activated with a
constraint profile from another project.

### 5.3 `planning.FeatureUnitRelation`

Models dependency and ordering without overloading the Feature Unit row.
Fields: `from_feature_unit_id`, `to_feature_unit_id`, `relation_type`
(`depends_on`, `blocks`, `relates_to`), `is_blocking`, `waived_by_decision_id`,
and `reason`. Unique `(from_feature_unit_id, to_feature_unit_id, relation_type)`.
No self-reference. Cycle detection is a transactional service validation; it
cannot be safely expressed as a portable row constraint.

### 5.4 `planning.AcceptanceCriterion`

Fields: `feature_unit_id`, `criterion_key`, `description`, `verification_mode`
(`command`, `artifact_review`, `human_check`, `mixed`), `is_required`,
`status`, `sort_order`, and `source_artifact_id`. Unique
`(feature_unit_id, criterion_key)` and `(feature_unit_id, sort_order)`.

### 5.5 `planning.HumanVerificationItem` And `HumanVerificationResult`

`HumanVerificationItem` defines a checklist requirement: `feature_unit_id`,
`item_key`, `title`, `instructions`, `is_required`, `sort_order`, and
`status_subject_id`.

`HumanVerificationResult` is append-only evidence: `item_id`, `decision_id`,
`result` (`passed`, `failed`, `skipped`), `reason`, `evidence_artifact_id`, and
`recorded_at`. A skipped required item needs a HumanDecision with explicit
reason. The current checklist display is derived from the latest valid result,
not overwritten on the item.

## 6. Component Work Tables

### 6.1 `components.ComponentWork`

Component Work is the implementation and PR unit. It has one repository and is
either `single` (one declared Component root) or `coordinated` (multiple
declared Component roots on one branch/PR).

Fields: `feature_unit_id`, `component_id`, `repository_id`,
`component_work_key`, `execution_scope`, `title`, `intent`, `risk_level`, `status_subject_id`,
`constraint_profile_id`, `verification_profile_id`, `base_branch`,
`head_branch`, `allowed_paths_version`, `is_required`, and `sequence_number`.

Unique constraint: `(feature_unit_id, component_work_key)`. Check that
`base_branch` equals the repository integration branch at creation and that
`head_branch` follows the ADO branch rule using `component_work_key`. The
`component_id` is the primary Component. A change to the repository mapping,
scope, constraint profile, or allowed paths after `branch_created` creates a
new Component Work revision rather than mutating execution scope.

### 6.2 `components.ComponentContract`

Represents an explicit cross-component interface or coordinated change.
Fields: `feature_unit_id`, `contract_key`, `title`, `contract_type`,
`producer_component_id`, `consumer_component_id`, `spec_artifact_id`,
`contract_status`, `approved_by_decision_id`, `is_required`, and `version`. Unique
`(feature_unit_id, contract_key)`. A required contract must be accepted before
dependent Component Work can reach `ready_for_pr`.

### 6.3 `components.ComponentWorkScope`

`ComponentWorkScope` binds immutable participating Components to a Component
Work: `component_work_id`, `component_id`, `repository_id`, `relative_root`,
`scope_role` (`primary`, `contributing`, `shared_contract`), `is_required`, and
`source_mapping_id`. Unique `(component_work_id, component_id)` and
`(component_work_id, relative_root)`. The primary scope must equal the parent
ComponentWork `component_id` and has `scope_role=primary`.

`single` Work has exactly one primary scope. `coordinated` Work has exactly one
primary scope and at least one contributing/shared-contract scope. All scope
entries must have the parent Repository and Project and must match an approved
ComponentRepository mapping. These are transaction-level validations in
addition to foreign keys and unique constraints.

### 6.4 `components.ComponentWorkRelation` And `AllowedPathRule`

`ComponentWorkRelation`: `from_component_work_id`, `to_component_work_id`,
`relation_type` (`depends_on`, `blocks`, `shares_contract`, `must_run_with`),
`is_blocking`, `waived_by_decision_id`, `reason`. Unique triple and no
self-reference.

`AllowedPathRule`: `component_work_id`, `path_pattern`, `access_mode`
(`read`, `write`), `is_required`, `sort_order`, `created_from_artifact_id`.
Unique `(component_work_id, path_pattern, access_mode)`. Patterns are
normalized and matched by a single vetted matcher; arbitrary shell glob syntax
is not executed.

## 7. Artifact And Document Tables

### 7.1 `artifacts.Artifact`

An Artifact is an immutable, addressable payload plus its provenance. Its
semantic status is the current status of `status_subject_id`, not a separately
writable Artifact column.

| Field | Type | Notes |
|---|---|---|
| `project_id` | FK Project | Required. |
| `artifact_key` | varchar | Unique within project. |
| `artifact_class` | enum | `source`, `generated`, `human`, `external`. |
| `artifact_type` | enum/string | Stable types such as `context_packet`, `git_diff`, `stdout_log`. |
| `status_subject_id` | one-to-one StateSubject | `draft`, `valid`, `superseded`, `rejected`, `quarantined`, `redacted`, `expired`, `deleted`. |
| `content_sha256` | char(64), nullable | Required for retained content. |
| `storage_locator` | varchar, nullable | Opaque non-secret object/path locator. |
| `mime_type` | varchar | Required. |
| `byte_size` | bigint | Non-negative. |
| `schema_version` | varchar, nullable | Required for structured output. |
| `redaction_status` | enum | `not_required`, `pending`, `passed`, `failed`. |
| `data_classification` | enum | `public`, `internal`, `restricted`, `quarantined`. |
| `source_version` | varchar, nullable | Source snapshot/version. |
| `context_hash` | char(64), nullable | Required for packets/documents where applicable. |
| `supersedes_id` | self FK, nullable | Never changes historical record. |
| `retention_until` | timestamptz, nullable | Retention policy result. |

Unique `(project_id, artifact_key)`. Check `byte_size >= 0`, valid hash shape,
and that `quarantined` classification cannot have `redaction_status=passed`.
An artifact may be made inaccessible, but its metadata and hash remain for
audit unless legal deletion policy says otherwise.

### 7.2 `artifacts.ArtifactSourceRef` And `ArtifactEmbedding`

`ArtifactSourceRef` creates directed provenance edges:
`artifact_id`, `source_artifact_id`, `relation_type` (`derived_from`,
`contains`, `summarizes`, `redacted_from`, `imported_from`, `evidence_for`),
`created_by_actor_id`, and `note`. Unique `(artifact_id, source_artifact_id,
relation_type)`; no self-edge. Graph-cycle checks run in the service layer.

`ArtifactEmbedding` is optional and excluded from v1-alpha implementation.
Its future shape is `artifact_id`, `embedding_model`, `vector`,
`content_sha256`, `created_at`, with uniqueness on `(artifact_id,
embedding_model, content_sha256)`. A pgvector index is added only after a
measured retrieval use case; it is not a prerequisite for ADO control flow.

### 7.3 `documents.DocumentArtifact`, `ContextPacket`, And `ReviewPacket`

All are one-to-one extensions of an `Artifact` of an allowed type.

`DocumentArtifact`: `artifact_id`, `document_type`, `rendered_path`,
`frontmatter_json`, `generated_from_db`, `manual_edit_detected`, `is_stale`,
`source_db_version`, and `generated_at`.

`ContextPacket`: `artifact_id`, `target_state_subject_id`, `packet_role`,
`constraint_profile_id`, `effective_spec_library_revision_id`,
`spec_manifest_sha256`, `token_estimate`, `external_safe`,
`selection_manifest_json`, `redaction_report_artifact_id`, and `expires_at`.
The effective revision is required and must be approved when the packet is
created; a packet cannot be `external_safe=true` unless redaction passed.

`ReviewPacket`: `artifact_id`, `component_work_id`, `git_snapshot_id`,
`verification_run_id`, `effective_spec_library_revision_id`,
`spec_manifest_sha256`, `review_scope_json`, and `expires_at`.

## 8. Execution And Verification Tables

### 8.1 `execution.Job`

`Job` is the immutable logical request. Fields: `project_id`,
`job_key`, `job_type`, `target_state_subject_id`, `idempotency_key`,
`payload_artifact_id`, `priority`, `scheduled_at`, `max_attempts`,
`timeout_seconds`, `retry_policy_json`, `status_subject_id`, `created_by_actor_id`,
and `cancel_requested_at`.

Unique `(project_id, idempotency_key)` and `(project_id, job_key)`. Check
`max_attempts > 0`, `timeout_seconds > 0`, and non-negative priority. The
payload is immutable; changing it creates a new Job with a new idempotency key.

### 8.2 `execution.JobAttempt` And `WorkerRegistration`

`JobAttempt` records one lease/run cycle: `job_id`, `attempt_number`,
`attempt_status`, `worker_id`, `leased_at`, `lease_expires_at`,
`started_at`, `finished_at`, `heartbeat_at`, `timeout_at`, `exit_summary`,
`failure_code`, `result_artifact_id`, and `replacement_attempt_id`.

Unique `(job_id, attempt_number)`. A partial unique constraint allows at most
one attempt for a Job in `leased` or `running` state. An attempt terminal time
must be present iff it is terminal. `attempt_status` is an execution-history
fact maintained by the Job service; the logical Job StateSubject remains the
authoritative state-machine target. Historical truth is the attempt sequence.

`WorkerRegistration` holds `worker_key`, `capabilities_json`, `version`,
`started_at`, `last_heartbeat_at`, `status`, and `last_error_artifact_id`.
Unique `worker_key`. It is operational metadata, not an authority grant.

`execution.JobOutboxEvent` durably records post-commit work intent:
`project_id`, `event_key`, `event_type`, `target_state_subject_id`,
`payload_artifact_id`, `deduplication_key`, `created_at`, `published_at`,
`publisher_attempts`, and `last_failure_artifact_id`. Unique
`(project_id, deduplication_key)`. A StateMachine transaction inserts this row
with its StateTransition; an outbox publisher creates the next Job only after
that transaction commits.

### 8.3 `execution.AgentRun` And `CommandRun`

`AgentRun`: `job_attempt_id`, `role`, `provider`, `model_identifier`,
`sandbox_profile`, `input_packet_id`, `output_artifact_id`,
`raw_output_artifact_id`, `schema_name`, `schema_version`, `status_subject_id`,
`effective_spec_library_revision_id`, `spec_manifest_sha256`, `started_at`,
`finished_at`, `duration_ms`, `failure_code`, and `usage_event_id`. Its
revision/hash must equal the input ContextPacket or ReviewPacket revision/hash.

`CommandRun`: `job_attempt_id`, `verification_run_id` nullable,
`command_key`, `argv_json`, `cwd_locator`, `environment_profile_id`,
`status_subject_id`, `started_at`, `finished_at`, `exit_code`, `signal`,
`timed_out`, `stdout_artifact_id`, `stderr_artifact_id`, and `duration_ms`.

All command argv is stored as an array, never as an executable shell string.
Check that exactly one of `exit_code` and `signal` is set on a completed
process, except for a runner failure before process spawn.

### 8.4 `verification.VerificationProfile`, `VerificationCommand`, And `VerificationRun`

`VerificationProfile` is versioned configuration:
`project_id`, `profile_key`, `version`, `scope_type`, `status`,
`source_artifact_id`, `constraint_profile_id`, `description`, and
`approved_by_decision_id`. Unique `(project_id, profile_key, version)` and one
active version per `(project_id, profile_key)`.

`VerificationCommand`: `verification_profile_id`, `command_key`, `argv_json`,
`cwd_rule`, `timeout_seconds`, `is_required`, `sort_order`,
`allow_network`, and `expected_exit_codes_json`. Unique
`(verification_profile_id, command_key)`.

`VerificationRun`: `component_work_id`, `job_attempt_id`,
`verification_profile_id`, `git_snapshot_id`, `status_subject_id`,
`effective_spec_library_revision_id`, `spec_manifest_sha256`, `required_passed`,
`summary_artifact_id`, `started_at`, `finished_at`, and `failure_code`. A run
is valid evidence only when its profile, snapshot, and Spec Library revision
match the Component Work revision being evaluated.

## 9. Review And Revision Tables

### 9.1 `reviews.ReviewGroup` And `ReviewResult`

`ReviewGroup` records a review council invocation: `component_work_id`,
`review_packet_id`, `risk_level`, `required_reviewer_count`,
`status_subject_id`, `started_at`, `completed_at`, and `partial_policy_reason`.

`ReviewResult`: `review_group_id`, `reviewer_key`, `provider`,
`model_identifier`, `agent_run_id`, `result_status`, `result_artifact_id`,
`overall_risk`, and `completed_at`. Unique `(review_group_id, reviewer_key)`.
`result_status` is runner-local fact data; ReviewGroup is the stateful object.

### 9.2 `reviews.ReviewFinding`, `ArbiterDecision`, And `RevisionTask`

`ReviewFinding`: `review_result_id`, `finding_key`, `severity`, `category`,
`title`, `description_artifact_id`, `file_path`, `line_start`, `line_end`,
`suggested_fix_artifact_id`, `status`, and `deduplication_hash`. Unique
`(review_result_id, finding_key)`. Check line range ordering when both fields
exist.

`ArbiterDecision`: `review_group_id`, `agent_run_id`, `decision_artifact_id`,
`decision` (`ready_for_pr`, `needs_revision`,
`human_required`, `blocked`), `summary`, and `decided_at`. One active arbiter
decision per review group; a replacement supersedes the earlier record.

`RevisionTask`: `component_work_id`, `source_finding_id` nullable,
`source_decision_id` nullable, `revision_key`, `severity`, `expected_fix`,
`verification_requirement`, `task_status`, `created_context_packet_id`,
and `resolved_by_verification_run_id`. Unique `(component_work_id,
revision_key)`. At least one source reference is mandatory.

## 10. Policy, State, And Human Control Tables

### 10.1 `state.TransitionRequest`, `policy.PolicyDecision`, And `policy.EvidenceGateResult`

These persist the JSON schemas of the same name as relational records.

`TransitionRequest`: `request_key`, `project_id`, `target_state_subject_id`,
`expected_current_status`, `requested_transition`, `requested_next_status`,
`requested_by_actor_id`, `reason_artifact_id` nullable, `reason_text`,
`risk_level`, `idempotency_key`, `created_at`, and `request_payload_artifact_id`.
Unique `(project_id, idempotency_key)` and `request_key`. The exact schema
payload may be retained as an Artifact, but query-critical fields are columns.

`PolicyDecision`: `decision_key`, `transition_request_id`, `decision`,
`reason`, `evaluated_rules_artifact_id`, `missing_requirements_artifact_id`,
`required_human_action`, `decided_by_actor_id`, `expires_at`, and `decided_at`.
One decision per request version; a re-evaluation creates a successor linked by
`supersedes_id`.

`EvidenceGateResult`: `gate_result_key`, `transition_request_id`, `gate_name`,
`status`, `checked_evidence_artifact_id`, `missing_evidence_artifact_id`,
`rejected_evidence_artifact_id`, `warnings_artifact_id`, `reason`,
`checked_by_actor_id`, and `checked_at`. A passed result is immutable and only
valid for the referenced request.

### 10.2 `state.StateTransition`

Fields: `transition_request_id`, `policy_decision_id`, `evidence_gate_result_id`,
`target_state_subject_id`, `from_status`, `to_status`, `transition_name`,
`reason`, `applied_by_actor_id`, `audit_event_id`, and `applied_at`.

Unique `transition_request_id`; the same request can apply at most once. Check
that `applied_by_actor_id` is the registered State Machine actor. This record,
the state update, and its AuditEvent are inserted in one transaction.

### 10.3 `policy.SafetyEvent`, `audit.IncidentReport`, And `policy.PauseRecord`

`SafetyEvent`: `project_id`, `event_key`, `target_state_subject_id` nullable,
`severity`, `event_type`, `status_subject_id`, `summary`, `evidence_artifact_id`,
`detected_by_actor_id`, `occurred_at`, and `is_blocking`. Unique
`(project_id, event_key)`.

`IncidentReport`: `project_id`, `incident_key`, `severity`, `status_subject_id`,
`opened_by_safety_event_id`, `summary_artifact_id`, `opened_at`, `resolved_at`,
and `resolution_decision_id`. Unique `(project_id, incident_key)`. A critical
SafetyEvent opens an IncidentReport transactionally.

`PauseRecord`: `project_id`, `scope_state_subject_id` nullable,
`scope_type`, `reason`, `created_by_decision_id`, `created_by_actor_id`,
`active`, `started_at`, and `ended_at`. A partial unique constraint permits at
most one active pause for the same scope. Resume records a new HumanDecision;
it does not erase the pause.

### 10.4 `audit.HumanDecision` And `audit.ManualOverride`

`HumanDecision`: `project_id`, `decision_key`, `target_state_subject_id`,
`decision_type`, `decision`, `reason`, `actor_id`, `evidence_manifest_artifact_id`,
`expires_at`, `recorded_at`, and `supersedes_id`. `actor_id` must reference a
human Actor. Unique `(project_id, decision_key)`.

`ApprovalEvent` is the immutable approval specialization of a HumanDecision:
`human_decision_id`, `approval_type`, `approved_scope_artifact_id`,
`effective_from`, `effective_until`, and `revoked_by_decision_id` nullable.
It is one-to-one with the HumanDecision that granted approval. Feature Unit,
roadmap, profile, and human-verification approval gates reference this row when
they require an approval-specific fact.

`ManualOverride` is a narrow extension of HumanDecision: `decision_id`,
`policy_code`, `risk_acknowledgement`, `override_scope`, and `expires_at`.
It may not represent a v1 non-overridable action.

## 11. Git, PR, Budget, And Audit Tables

### 11.1 `gitops.GitWorktree`, `GitSnapshot`, And `PullRequest`

`GitWorktree`: `component_work_id`, `repository_id`, `worktree_key`,
`path_locator`, `branch_name`, `base_ref`, `worktree_status`, `created_at`,
`released_at`, and `cleanup_result_artifact_id`. One active worktree per
Component Work through a partial unique constraint. It cannot be created for a
protected or non-ADO branch.

`GitSnapshot`: `repository_id`, `component_work_id` nullable, `worktree_id`
nullable, `commit_sha`, `tree_sha`, `base_commit_sha`, `diff_artifact_id`,
`changed_paths_artifact_id`, `captured_at`, and `is_initial`. Unique
`(repository_id, commit_sha, tree_sha, component_work_id)`.

`PullRequest`: `component_work_id`, `repository_id`, `provider`,
`external_pr_number`, `external_pr_id`, `url`, `head_branch`, `base_branch`,
`status_subject_id`, `body_artifact_id`, `created_by_agent_run_id`,
`effective_spec_library_revision_id`, `spec_manifest_sha256`, `created_at`,
and `last_synced_at`. Unique `(repository_id, external_pr_id)` and
`(repository_id, external_pr_number)`. Check `base_branch` equals `integrate`;
v1 has no merge service or merge mutation field.

### 11.2 `policy.BudgetPolicy` And `policy.UsageEvent`

`BudgetPolicy`: `project_id`, `policy_key`, `period_kind`, `limit_kind`,
`limit_value`, `warning_threshold`, `status`, `approved_by_decision_id`, and
`effective_from/effective_until`. It records controls, not invented prices.

`UsageEvent`: `project_id`, `job_attempt_id` nullable, `agent_run_id` nullable,
`provider`, `model_identifier`, `usage_kind`, `quantity`, `unit`,
`cost_amount` nullable, `currency` nullable, `is_estimated`, `recorded_at`,
and `source_artifact_id`. Unknown costs remain null; a zero is never used to
mean unknown.

### 11.3 `audit.AuditEvent` And `audit.ExternalTransferEvent`

`AuditEvent` is append-only: `project_id`, `event_key`, `trace_id`,
`correlation_id`, `event_type`, `actor_id`, `target_state_subject_id` nullable,
`job_attempt_id` nullable, `payload_artifact_id` nullable, `summary`,
`occurred_at`, and `integrity_hash`. Unique `(project_id, event_key)`.

`ExternalTransferEvent`: `project_id`, `event_key`, `source_artifact_id`,
`packet_artifact_id`, `destination_kind`, `destination_reference`,
`redaction_status`, `human_preview_decision_id`, `policy_decision_id`,
`status_subject_id`, `occurred_at`, and `response_artifact_id` nullable.
Unique `(project_id, event_key)`. A transfer cannot be marked allowed without a
passed-redaction packet and, for Claude interactive, a human preview decision.

## 12. Cross-Table Integrity Rules

The service layer must validate the following in the same transaction as the
create/bind action; direct model saves are insufficient:

- All referenced Project, Repository, Component, Feature Unit, and Component
  Work rows are from the same project.
- A Component Work repository is mapped to its primary Component and every
  ComponentWorkScope; `single`/`coordinated` scope cardinality holds.
- ContextPacket, ReviewPacket, VerificationRun, GitSnapshot, AgentRun, and
  PullRequest refer to the same Component Work revision, project constraint
  profile, and effective SpecLibraryRevision/manifest hash.
- `Artifact` evidence is `valid`, non-stale, non-quarantined, and has an
  allowed classification before entering an EvidenceGateResult.
- HumanDecision and ManualOverride actors are human actors.
- A StateTransition uses an allowed StateMachine actor, allowed PolicyDecision,
  passed EvidenceGateResult, and the requested target/current status.
- A PR is only for the Component Work head branch and the repository
  integration branch.
- No active IncidentReport or PauseRecord blocks an automatable Job lease.

Database check constraints enforce local facts. Transactional services enforce
cross-row and graph facts. Both are required.

## 13. v1-alpha Delivery Boundary

The initial migration set must implement the following tables first:

1. `Actor`, `SpecLibraryRevision`, `Project`, `Repository`, `Component`,
   `ComponentRepository`, and `ProjectConstraintProfile`.
2. `Roadmap`, `RoadmapSource`, `FeatureUnit`, `AcceptanceCriterion`,
   `HumanVerificationItem`, and `FeatureUnitRelation`.
3. `ComponentWork`, `ComponentWorkScope`, `AllowedPathRule`, `Artifact`, `ArtifactSourceRef`,
   `DocumentArtifact`, and `ContextPacket`.
4. `StateSubject`, `TransitionRequest`, `PolicyDecision`,
   `EvidenceGateResult`, `StateTransition`, and `AuditEvent`.
5. `Job`, `JobAttempt`, `WorkerRegistration`, `AgentRun`, and `CommandRun`.

Verification, review, git/PR, incident, budget, and embedding models may land
as later v1-alpha migrations, but their contracts above are fixed now. No
future table may weaken the state, evidence, audit, or project-boundary
invariants.

## 14. Acceptance Criteria

This database model is complete when implementation evidence proves:

- every master-spec core entity has a named relational owner;
- all important state is owned by `StateSubject` and applied only through the
  State Machine transaction;
- retries preserve attempts and lease history;
- every artifact, decision, evidence gate, transition, audit event, run, and
  external transfer is project-scoped and addressable;
- critical relations have foreign keys, local invariants have constraints, and
  operational queries have named indexes in `DATABASE_CONSTRAINTS.md`;
- secrets and production data are structurally excluded from persisted payloads;
- the database can reconstruct a Component Work, its evidence, and its PR
  without trusting a worktree or Markdown file.
